# 対馬市版 移行実装記録

基準: [移行設計書](20260922_2238_対馬市版移行設計書.md)。実装ブランチ: `feat/tsushima-migration`、PRのベース: `Tsushima-city/develop`。

## 実装済み

- web/adminのサイト名、自治体名、公式議案URL、会派例、運営者zawa、LINE連絡先、長崎地方裁判所、共有ハッシュタグを変更。
- `managingParty` はサイト運営主体の政党名であり、掲載する議員の党派・会派とは別。空文字を維持し、政党紹介は無効。
- 問題報告・紹介記事URLが未設定の場合は該当リンクを非表示。非公式運営時のデスクトップ寄附リンクも非表示。
- manifestの名称・説明、対馬市版ロゴ、PWAアイコン（192/512/180px）、開発用アイコン、1200×630pxのOGP、トップ背景を更新。
- OGPと背景は画像生成による暫定イラスト。地図・地形の測量資料や現地写真ではない。ロゴは海と対話を表すSVG。原作紹介のチームみらいロゴは帰属説明用に保持。
- シードを設計書の会期1件・会派7件・委員会6件に変更。確認待ち会期は `is_active: false`。既存行は上書き・削除せず、同名の行がない場合のみ追加する。
- 旧地域の架空議案・説明・賛否・インタビューデモの投入処理と未使用テンプレートを削除。実際の対馬市議案・採決結果は管理画面から資料と照合して登録する。
- 現行のローカルAIプロンプト3種（トップ・通常・詳しい）を対象議会・運営者に合わせ、各党派・会派を同じ基準で扱う方針に変更。
- 環境変数テンプレートに未設定項目を整理。秘密値・契約・公開URLの発行はしていない。
- AGENTS.md、CIのブランチフィルタ、デプロイのcheckout先を `Tsushima-city/develop` に変更。

## 公開前に残る作業

1. Supabaseの対馬市専用環境と公開Web/Admin URLを用意し、`.env.example` / `.env.production.example` を参考に値を設定する。
2. 会期の確定日程、会派・委員会の現況を確認する。シードは既存DB内の旧地域データを除去しないため、旧データがある場合は移行方針を別途決める。同時シード実行を避け、まず検証用DBで初回・再投入を確認する。
3. 公式資料に基づく議案・議決結果を登録し、公開対象会期を有効化する。議員個人の党派表示を追加する場合は別途実装が必要。
4. AI Gateway・画像生成・Langfuse等のキーと利用予算を設定し、実接続で動作確認する。設計書のLangfuse4種の説明と現行コードには差があり、トップ・通常・詳しいはローカル管理。それ以外のプロンプトはLangfuseにフォールバックするため、利用時に地域情報・運営主体を確認する。
5. 問題報告フォームと紹介記事のURLが決まったら `web/src/config/site.config.ts` へ設定する。未定の間は運営者のLINE連絡先を利用する。
6. デプロイワークフローは現行どおり `staging` を参照する（`main` のみproduction扱い）。公開環境を決めてからGitHub EnvironmentとSupabase/VercelのSecretsを設定する。本実装ではデプロイ・マイグレーションを実行していない。
7. 各画面・AI応答・画像の見え方を実環境で確認し、設計書のリリース前チェックリストを完了する。
